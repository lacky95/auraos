The `aura` CLI drives AuraOS from a terminal: apps, instances, sidecars,
capabilities, mounts, ports, the event bus, sandbox shells. Source:
`packages/aura-cli/src/` (`program.ts` builds the command tree,
`commands/verbs.ts` the kubectl verbs, `lib/resources.ts` the resource types).

`aura --help` prints the grouped overview; `aura <command> --help` shows the
resources a verb accepts plus examples.

## The grammar in one minute

Everyday work has **short forms**; everything else reads like kubectl —
**`aura <verb> <resource> [name…]`**:

```bash
aura ps                                    # running instances
aura run com.aura.notepad                  # start an app
aura jump com.aura.terminal                # shell into its sandbox
aura get apps -o wide                      # any resource as a table, json, yaml or names
aura get inst io.lakner.hermes sidecars    # the sidecars of one instance, with their IDs
aura jump io.lakner.hermes --sidecar runtime
aura describe inst com.aura.terminal       # everything about one object
aura stop app com.aura.notepad
aura api-resources                         # every resource type + its verbs
```

Short names work wherever a resource is expected (`inst`, `sc`, `act`, …),
and an instance can be named by its app id when exactly one instance of it is
running.

## Short forms

| Command | Description | Key flags |
|---|---|---|
| `aura ps` | docker-ps-style table of instances (INSTANCE, APP, STATE, PORT, ACTIVITIES, UPTIME). Same data as `aura get inst`. | `-w, --watch` |
| `aura run <appId>` | Start an app; prints the new instance id. | — |
| `aura jump [target]` (alias `j`) | Without a target: interactive picker. With an app id or instance id: straight into that sandbox. | `-s, --sidecar <id>`, `-m, --master`, `--no-apps`, `--no-services` |
| `aura info` | Where am I? Layers (host / aura-shell / proot / container), OS, CPU, memory, namespaces, AuraOS env, mounts, tools. | `--json` |
| `aura status` | AuraOS health summary: shell, apps, capabilities, services, paths. | — |

`aura jump --sidecar <id>` enters a sidecar of the target (bash if the image
has it, else sh); without a target it means a sidecar of the app you are in.
`aura jump -m` drops into the `aura-shell` master container. Jumping into a
container needs the docker CLI and socket in the calling sandbox — the
Terminal and the master shell have both.

## Resource types

| Resource | Short names | Verbs |
|---|---|---|
| `apps` | `app` | get, describe, run, stop, restart, delete, install, enable, disable, grant, revoke |
| `instances` | `instance`, `inst` | get, describe, stop, kill, pause, resume, exec, logs |
| `sidecars` | `sidecar`, `sc` | get, describe, exec, logs, delete |
| `activities` | `activity`, `act` | get, open, delete |
| `capabilities` | `capability`, `caps`, `cap` | get, describe, install, delete, grant, revoke |
| `services` | `service`, `svc` | get, describe, start, stop, install, delete, logs |
| `mounts` | `mount` | get, delete |
| `ports` | `port` | get, delete |
| `scopes` | `scope` | get |
| `themes` | `theme` | get, set |
| `permissions` | `permission`, `perms`, `perm` | get, grant, revoke |

`aura api-resources` prints the same table from the CLI itself.

## Resource verbs

| Command | Description | Key flags |
|---|---|---|
| `aura get <res> [name]` | List as a table. A name narrows to one object. | `-o table\|wide\|json\|yaml\|name`, `-a, --app <appId>`, `-i, --instance <id>`, `-w, --watch`, `--no-headers` |
| `aura get inst <id> sidecars` | The sidecars of one instance — the **ID** column is what `--sidecar` / `-c` take. | same as `get` |
| `aura describe <res> <name>` | Everything about one object, as YAML (`-o json` for JSON). `describe inst` includes its sidecars and mounts. | `-o json`, `-i <instance>` (sidecars) |
| `aura stop app\|inst\|svc <name…>` | Stop all instances of an app, one instance (graceful: `onPause` → `onStop` → `onDestroy`), or a service. | — |
| `aura start svc <name…>` | Start a service detached. (Apps start with `aura run`.) | — |
| `aura restart app <appId…>` | Stop all instances, start one fresh. | — |
| `aura kill inst <id…>` | SIGKILL the sandbox; no lifecycle hooks. | — |
| `aura pause\|resume inst <id…>` | Fire `onPause` / `onResume`. | — |
| `aura delete <res> <name…>` (alias `rm`) | Remove an app from disk, close an activity, uninstall a service or capability, detach a mount, remove a port expose, delete an OS sidecar. | `-y` (apps), `-i <instance>` (mounts, sidecars) |
| `aura install app <path>` | Install an app from a local directory (`app.manifest.json` inside). | — |
| `aura install cap <name…>` / `svc <name>` | Install capabilities into the shared toolchain / a service. | — |
| `aura install sdk` | Pull every `@aura/*` package the cwd's `package.json` declares (in `auraDependencies`) from the local OCI registry. | `--quiet`, `--registry <url>`, `--cwd <path>` |
| `aura enable\|disable app <appId…>` | Re-arm `autoStart`/`warmPool` and show in dock + launcher / stop every instance and hide it. | — |
| `aura open act <instance>` | Open a new activity (window) on a running instance. | `-d, --data '<json>'` |
| `aura exec inst <id> [-- cmd…]` | Interactive shell in the sandbox, or run one command after `--`. Exit codes pass through. | `-c, --container <sidecar>` — a sidecar of the instance instead |
| `aura logs inst <id> -c <sidecar>` | A sidecar's logs. Inside the app that owns an OS sidecar the OS serves them; elsewhere `docker logs`. | `-f, --follow`, `--tail <n>` |
| `aura logs svc <name>` | Service logs (not implemented yet). | — |
| `aura grant perm <appId> [permission…]` | Add manifest permissions; takes effect immediately. No permissions → picker (unchecking revokes). | — |
| `aura grant cap <appId> [cap…]` | Add to the app's `tools[]` and hot-refresh running instances. `'*'` grants all, `'#'` all-except. No names → picker. | `-i, --interactive` |
| `aura revoke perm\|cap <appId> <name…>` | The opposite of `grant`. | — |
| `aura get perms [appId]` | Declared permissions per app. | — |
| `aura set theme <id>` | Set the active theme for a tone slot; live update across the shell and apps. | `--tone dark\|light` |
| `aura api-resources` | Resource types, short names, verbs. | — |

Examples:

```bash
aura get inst -a com.aura.terminal -o name     # inst/com.aura.terminal-13 …
aura get sc -a io.lakner.hermes -o wide        # + CONTAINER, TEMPLATE
aura get mounts -i com.aura.terminal           # app + its OS sidecars' mounts
aura describe sc runtime -i io.lakner.hermes
aura exec inst io.lakner.hermes -c runtime -- hermes --version
aura delete mount com.example.hello -i com.aura.terminal
aura delete port com.aura.browser into-5173    # <ownerApp> <portId>
aura grant perm com.example.app sidecars.spawn
```

### Sidecars from the CLI

`aura get sc` lists both kinds: **MANAGED `os`** sidecars the OS started for
an app ([Sidecars](/docs/sidecars)) and **`app`** sidecars an app runs itself.
The ID is the sidecar name (or the container name for raw containers without
an `aura.service` label). `aura delete sc <id>` only applies to OS sidecars
and needs that app's token — run it inside the app (`aura jump <app>` first);
app-managed sidecars belong to their app.

## Tools

These keep their own subcommands.

### Mounts — `aura mount …`

| Command | Description | Key flags |
|---|---|---|
| `aura mount` | Wizard: target app → instance → the set of apps mounted into it. | — |
| `aura mount ls` | What is mounted into an instance, its OS sidecars' mounts, and the OS context volumes. | `--instance <id>` |
| `aura mount add [appId…]` | Mount apps (read-only by default). No ids → picker. | `--wr`, `--data`, `--instance <id>` |
| `aura mount rm [appId…]` | Detach; `<appId>:data` drops just the data mount. | `--all`, `--instance <id>` |

`--instance` defaults to `$APP_INSTANCE_ID`. See [Cross-App Mounts](/docs/cross-app-mounts).

### Ports — `aura port …`

| Command | Description | Key flags |
|---|---|---|
| `aura port ls [app]` | Port exposes (OWNER, ID, KIND, SOURCE, LISTEN, STICKY). | — |
| `aura port expose <srcApp:port> --into <targetApp>` | Make a port appear on another app's `127.0.0.1`. | `--port <n>`, `--sticky` |
| `aura port expose <srcApp:port> --host [addr]` | Publish on the host (default bind `127.0.0.1`). | `--host-port <n>`, `--sticky` |
| `aura port rm <ownerApp> <portId>` | Remove an expose. | — |

### Capabilities — `aura cap …`

`cap install` adds a tool to the OS-wide toolchain; `grant cap` exposes it
inside one app's sandbox (`/aura/my-tools`).

| Command | Description | Key flags |
|---|---|---|
| `aura cap list` | Registry inventory (same as `aura get caps`). | `--installed`, `--available` |
| `aura cap info <name>` | Registry entry + install status + declaring apps. | — |
| `aura cap install <name…>` | Install (apt/npm/curl per registry entry). | — |
| `aura cap remove <name>` | Uninstall and strip from every manifest. | — |
| `aura cap grant [appId] [name…]` / `revoke <appId> <name…>` | Same as `aura grant/revoke cap`. | `-i` |
| `aura cap doctor [name…]` | Can each installed capability actually RUN in each sandbox? | `--fix`, `--no-probe`, `--json` |
| `aura cap registry show\|add\|remove` | Inspect or edit the capability registry YAML. | `--source`, `--package`, `--binary`, `--url` |

### App store — `aura nexus …`

Publish, install, update apps and manage registries; every command posts to
the shell's `/api/nexus/*` endpoints. See [Nexus](./nexus) and
[Publish an App](./publish-an-app). (The old flat spellings —
`aura nexus install`, `aura nexus publish`, … — still work, hidden.)

| Command | Description | Key flags |
|---|---|---|
| `aura nexus app publish [<path>]` | Push the app to a registry (OCI) or git repo. Bare + TTY = wizard. | `--to`, `--kind oci\|git`, `--tag`, `--channel`, `--branch`, `-y`, `--submit` |
| `aura nexus app submit [<path>]` | Open a store PR for a published app. | `--from`, `--tag`, `--channel`, `--store-repo`, `--dry-run` |
| `aura nexus app install <ref>` | Resolve, fetch, validate, install. Pauses on new-permission diffs unless `-y`. | `-y`, `--channel`, `--scope global\|user` |
| `aura nexus app update [<id>\|--all]` | Reinstall if the stored ref moved. | `-y`, `--all` |
| `aura nexus app uninstall <id>` | Remove; `--purge` also wipes its data. | `--purge` |
| `aura nexus app list` / `info <ref>` | Installed apps / dry-run preview of a ref. | `--source` |
| `aura nexus app screenshots list\|add\|replace\|remove` | Manage store screenshots. | `--store-repo`, `--dry-run` |
| `aura nexus store login\|status` | Store GitHub token / show the store target. | — |
| `aura nexus registry add\|list\|remove` | Manage sources. | `--kind`, `--priority`, `--mirror`, `--ref` |
| `aura nexus search [<q>]` | Search the aggregated catalog. | `--category`, `--refresh` |

Ref shapes `install` / `info` accept:

| Shape | Example |
|---|---|
| Store id | `com.example.foo`, `com.example.foo@beta` |
| OCI | `oci://ghcr.io/u/foo:1.2.3`, `ghcr.io/u/foo@sha256:…` |
| Git URL with optional ref | `https://github.com/u/r#main`, `github.com/u/r#v1.2.3` |
| Local path | `./apps/com.example.foo`, `/abs/path` |

### Dev tools — `aura dev …`

| Command | Description | Key flags |
|---|---|---|
| `aura dev new [appId]` | Scaffold a new app. Wizard if `appId` is omitted. | `--name`, `--icon`, `--description`, `--shape`, `--instance-mode`, `--sandbox`, `--tools`, `--scope`, `--force`, `--non-interactive` |
| `aura dev clone [source] [target]` | Clone an app (any scope) into `user` or `global`. | `--scope`, `--name`, `--no-rewrite-ids`, `--with-data`, `--dry-run`, `--json`, … |
| `aura dev validate [path]` | Zod-validate one manifest, or all with `--all`. | `--all` |
| `aura dev clean-manifest [path]` | Strip fields equal to schema defaults. | `--all`, `--dry-run` |
| `aura dev standalone <appId>` | Run an app with `astro dev`, outside the shell. | — |

### Event bus — `aura events`

`aura events [-f <pattern>]` follows the OS event bus. The filter takes an
exact type or a trailing `*` (`app:*`).

### Content providers — `aura data …`

| Command | Description | Key flags |
|---|---|---|
| `aura data query <authority>/<path>` | GET from a provider; print JSON. | — |
| `aura data write <authority>/<path> [body]` | Write; body `-` reads stdin. | `-m, --method PUT\|POST\|DELETE` |
| `aura data watch <authority>/<path>` | Follow an SSE provider. | — |

## The previous grammar

Before the kubectl grammar, resources had command groups. They **still work**
— hidden from `--help`, and a human (TTY) gets a one-line hint naming the new
form. Scripts are unaffected; `aura sdk install` (run on every app boot) never
prints a hint.

| Before | Now |
|---|---|
| `aura app list` / `info` / `start` / `stop` / `restart` | `aura get apps` / `describe app` / `run` / `stop app` / `restart app` |
| `aura app install` / `remove` / `enable` / `disable` | `aura install app` / `delete app` / `enable app` / `disable app` |
| `aura app perm ls` / `grant` / `revoke` | `aura get perms` / `grant perm` / `revoke perm` |
| `aura inst list` / `info` / `stop` / `kill` / `pause` / `resume` | `aura get inst` / `describe inst` / `stop inst` / `kill inst` / `pause inst` / `resume inst` |
| `aura inst shell <id> [-c cmd]` | `aura exec inst <id> [-- cmd]` or `aura jump <id>` |
| `aura activity list` / `open` / `close` | `aura get act` / `open act` / `delete act` |
| `aura service list` / `install` / `start` / `stop` / `status` / `uninstall` | `aura get svc` / `install svc` / `start svc` / `stop svc` / `describe svc` / `delete svc` |
| `aura theme list` / `get` / `set` | `aura get themes` / `set theme` |
| `aura scope list` | `aura get scopes` |
| `aura sdk install` | `aura install sdk` |
| `aura whereami` | `aura info` |

Set `AURA_DEPRECATION_HINTS=0` to silence the hints.

## Built-in and global options

| Command / option | Effect |
|---|---|
| `aura completion bash\|zsh` | Completion script: commands, resource types, and live names (apps, instances). `eval "$(aura completion bash)"`. |
| `--shell-url <url>` | Override the shell URL (default `$OS_API_BASE`, else `http://127.0.0.1:3000`). |
| `-V, --version` | CLI version. |
| `-h, --help` | Overview, or one command's usage with `aura <command> --help`. |

Extra positional arguments are an error, not silently ignored.
