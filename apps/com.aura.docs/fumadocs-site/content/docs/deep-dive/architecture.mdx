**TL;DR.** One shell process (`aura-shell` container) hosts the AppManager,
the App Host router, the machine proxy, the content-provider router, the
SSE/socket.io event bus, the theme manager, the keymap registry, and the
launcher UI. **N app processes** (PRoot or Docker sibling containers) each run
their own framework (Astro by default, or anything via raw runtime). The
browser reaches an app window only on that app's own App Host origin, which
the shell streams to the app; apps never see the browser directly.

## Package map (`packages/`)

| Package | What it is | Key files |
|---|---|---|
| `@aura/core` | The OS brain. Lifecycle FSM, port allocator, sandbox runners, theme/keymap/intent registries, content-provider router, event bus, **Nexus**. | `app-manager/`, `theme/`, `keymap/`, `nexus/`, `ipc/OsEventBus.ts` |
| `@aura/shell` | The Astro SSR app that draws the desktop + routes App Hosts + serves the machine proxy, the content-provider router and the WS-upgrade proxy. | `server/app-hosts.mjs`, `server/app-gateway.mjs`, `src/pages/api/proxy/[id]/[...path].ts`, `src/pages/index.astro`, `astro.config.mjs` (the `wsProxyPlugin`) |
| `@aura/app-sdk` | The library every app imports. Lifecycle factories, `OsClient`, `auraAppIntegration()`, raw-runtime adapters. | `src/lifecycle.ts`, `src/OsClient.ts`, `src/integration.mjs`, `src/runtime/next.ts` |
| `@aura/ui` | shadcn/scificn React primitives. Card, Dialog, Spinner, Checkbox, etc. | `src/components/`, `src/styles/scificn-bridge.css` |
| `@aura/kv-store` | Tiny Redis-backed KV client; backing store for theme prefs, workspace state, app enable map. | `src/index.ts` (server + browser flavours) |
| `@aura/aura-cli` | The `aura` command. Talks to the shell via HTTP. | `src/index.ts`, `src/commands/*.ts` |

## How a click ends up running app code

The full path of a single user click from the launcher to "iframe paints":

```
1.  User clicks launcher tile
       └─► window.auraLaunchApp(appId)         (shell front-end)
2.  Front-end issues POST /api/apps/<appId>/start
3.  AppRegistry resolves the manifest
       └─► AppManager.start(appId)
4.  AppManager:
     ─ allocates a port (PortAllocator)
     ─ mints the instance token (InstanceTokens → AURA_INSTANCE_TOKEN)
     ─ picks a runner (sandbox: 'proot' | 'container')
     ─ calls runner.spawn(instanceId, appId, port, manifest)
        ProotRunner       → bash entrypoint inside PRoot
        ContainerRunner   → docker run aura-base + entrypoint
     ─ re-applies declared cross-app mounts and port exposes
5.  Runner waits for /api/lifecycle/health
       └─► verifyHealthIdentity() — the X-Aura-* echo gate
6.  AppManager calls onCreate, onStart, onResume in sequence
7.  Instance state ↦ 'resumed' on the FSM
8.  AppManager emits app:stateChanged on OsEventBus
9.  The shell front-end (subscribed via SSE) receives the event
       └─► pushes an iframe slot for the instance's App Host,
           {label}--{desktop host}, into the active workspace layout
10. The iframe signs in with a one-time handoff, then loads:
       └─► the App Host router resolves the label → streams the
           request to the instance, nothing rewritten
       └─► the page loads /_aura/runtime.js (theme, keymap, console
           relay, keyboard per manifest.proxy.inject*) and reaches
           the shell through /_aura/os/
11. App's HTML lands in the browser. First paint.
```

Every step is a reachable function with a real source location. The
rest of this section walks each box.

Sidecars hang off step 6 onwards: the app asks the OS to start one
(`POST /api/instances/<id>/sidecars` with its token), `SidecarManager`
resolves the request against the app's `services[]` templates and runs the
container next to the instance on `aura-net`, then `MountManager` applies the
sidecar's own and inherited mounts. On stop or crash the instance's sidecars
are reaped with it. See [Sidecars](/docs/sidecars).

## Read the source

For when this page is out of date:

```sh
# Master container shell — see what's actually wired.
aura jump --master

# AppManager FSM and start path
$ less packages/core/src/app-manager/AppManager.ts

# OS-managed sidecars, their mounts, instance tokens
$ less packages/core/src/app-manager/SidecarManager.ts
$ less packages/core/src/app-manager/MountManager.ts
$ less packages/core/src/app-manager/InstanceTokens.ts

# App Host router, runtime script and gateway
$ less packages/shell/server/app-hosts.mjs packages/shell/server/app-gateway.mjs

# Machine proxy
$ less packages/shell/src/pages/api/proxy/\[id\]/\[...path\].ts

# WS upgrade chain (its own Vite plugin)
$ less packages/shell/astro.config.mjs   # search for wsProxyPlugin

# AppRegistry chokidar watcher
$ less packages/core/src/app-manager/AppRegistry.ts

# OsEventBus topic shape
$ less packages/core/src/ipc/OsEventBus.ts
```
