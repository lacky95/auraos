---
title: Proxy + iframe
description: How app windows reach their app (App Hosts) and how machines reach it (/api/proxy/<id>/<path>) — the two paths, step by step.
---

**TL;DR.** An app window is an iframe on the app's own **App Host**,
`{label}--{desktop host}`. The shell's Host router streams those requests to
the instance with nothing rewritten; the page gets its OS integration from
`/_aura/runtime.js` and reaches the shell through `/_aura/os/`.
`/api/proxy/<id>/<path>` is the **machine proxy**: agents' MCP URLs, one
app's server calling another. It refuses browser documents, strips its
prefix, and never touches HTML.

Source of truth: `packages/shell/server/app-hosts.mjs` (App Hosts),
`packages/shell/server/app-gateway.mjs` (`/_aura/runtime.js`, `/_aura/os/`),
`packages/shell/src/pages/api/proxy/[id]/[...path].ts` (machine proxy).

## Windows: the App Host

```
http://notesabcd1234--10-0-0-2.nip.io:3000/<path>
       ▲            ▲
       │            └── the host AuraOS is open at
       └─────────────── label from the App Host registry (one per installation
                        and instance slot)
```

1. **Host router.** The shell checks `Host` before anything else. A label the
   registry knows goes to the instance holding it; an unknown label answers
   *404*, a removed app's label *410*. Every other host goes on to the shell.
2. **Handoff.** The desktop signs the window in with a one-time handoff that
   sets an app cookie on that origin. Without it nothing reaches the app.
3. **Reserved paths.** `/_aura/*` is answered by the shell, never by the app:
   `/_aura/runtime.js` and the gateway `/_aura/os/` (the shell's API, checked
   against the app's own access rules).
4. **Stream.** Everything else is streamed to the instance: same path, no
   rewriting, no injected scripts. The shell drops its own credentials, adds
   `X-Forwarded-*`, `X-Aura-App-Id` and `X-Aura-Instance-Id`, and keeps
   `Host`. WebSocket upgrades are piped byte for byte.
5. **Start on demand.** A stopped instance is started by the first request;
   meanwhile the browser gets a page that reloads itself (*503*).

The page loads `/_aura/runtime.js` itself (Astro apps through
`auraAppIntegration()`, others through `AURA_RUNTIME_LOADER_JS`). The runtime
sets `window.AuraRuntimeBootstrap` and installs what the manifest's `proxy`
flags allow:

| Flag | Default | What the runtime installs |
|---|---|---|
| `injectMeta` | `true` | The OS theme stylesheet, for `inherit` apps |
| `injectConsoleRelay` | `true` | Relays `console.*` and uncaught errors to the shell |
| `injectKeyForwarder` | `true` | Forwards claimed OS shortcuts and the on-screen keyboard |
| `injectInputCompat` | `true` | Mouse-to-touch replay on touch browsers |
| `injectEventSourceMux` | `true` | Same-origin `EventSource` streams over one WebSocket |

Details for app authors: [Building an app for App Hosts](/docs/building-for-app-hosts).

## Machines: `/api/proxy/<id>/<path>`

```
/api/proxy/<id>/<path>?<query>
            ▲    ▲
            │    └── forwarded to the instance as /<path>?<query>
            └────── instance id, or bare app id (the resolver picks the live instance)
```

In order:

1. **Resolve the instance.** Exact instance id, else the first live
   (non-pool) instance of the app id. *503* while none has a port.
2. **Refuse browser documents.** A navigation or a frame (`Sec-Fetch-Dest`
   `document`, `iframe`, `frame`, `embed`, `object` or `worker`;
   `Sec-Fetch-Mode: navigate`; or `Upgrade-Insecure-Requests`) gets *403*.
   Windows open on App Hosts only.
3. **Service guard.** A `service` app answers only `/api/…` here, unless its
   manifest sets `proxy.exposeAllPaths` (e.g. the registry's `/v2/`).
4. **Forward.** The `/api/proxy/<id>` prefix is stripped, so the agents' MCP at
   `/api/proxy/com.aura.docs/mcp` reaches Docs as `/mcp`. The shell stamps `X-Aura-App-Id` and
   `X-Aura-Instance-Id` and streams the body.
5. **Identity gate.** If the response carries an `X-Aura-App-Id` that doesn't
   match the resolved instance, the body is dropped and the caller gets *502*
   (port-squat protection).
6. **Respond.** The body passes unchanged: no HTML or JS rewriting, nothing
   injected. `Set-Cookie` is dropped, `Content-Encoding`/`Content-Length` are
   removed (Node's fetch already decompressed the body), and every response
   carries `Content-Security-Policy: sandbox`, so nothing it returns can run
   as a page on the desktop's origin.

WebSocket upgrades on the same URL shape go through a Vite plugin in
`packages/shell/astro.config.mjs` (`wsProxyPlugin`), which resolves the
upstream through `/api/apps` and pipes the upgrade with `ws`.

## Failure modes

| Symptom | Cause | Where to look |
|---|---|---|
| **403** opening `/api/proxy/<id>/` in a browser tab | The machine proxy refuses documents | Open the app from the desktop; it runs on its App Host |
| **503** on a window or a machine call | Instance not yet `resumed`; warm-pool race | `AppManager.start()` + `waitHealthy` |
| **502** with `[proxy] identity mismatch` log | Different process bound the port; squatter | The identity gate in the proxy file |
| **404** *No app uses this address* | The label isn't in the App Host registry | `aura get apps`; open the app from the desktop again |
| **404** on `/api/lifecycle/health` for a raw app | The app serves its routes under a base path | Serve from `/`: the runner calls `/api/lifecycle/*` directly |
| Blank iframe, no errors | The app sends `X-Frame-Options: DENY` or a `frame-ancestors` that leaves out the desktop | The app's response headers |

## Reading the source

```sh
aura jump --master
$ less packages/shell/server/app-hosts.mjs        # Host router, handoff, streaming
$ less packages/shell/server/app-gateway.mjs      # /_aura/runtime.js and /_aura/os/
$ less packages/shell/src/pages/api/proxy/\[id\]/\[...path\].ts   # machine proxy
```

The proxy route reloads on save. `server/*.mjs` and the WS plugin in
`astro.config.mjs` need a shell restart.
