---
title: Reaching AuraOS
description: Open AuraOS at a nip.io address (no domain needed) or at your own domain, and what each gives you.
---

**TL;DR.** Without a domain, open AuraOS at
`http://<ip-with-dashes>.nip.io:3000`, e.g. `http://10-0-0-2.nip.io:3000`.
With a domain, put an HTTPS edge in front and route `host` and
`*--host` to the shell. Both support everything, including
[App hosts](/docs/app-hosts); only a domain gives you HTTPS.

## The ways in

| Access | Example | App hosts | HTTPS-only browser APIs |
|---|---|---|---|
| **Custom domain** (recommended) | `https://lukas-01.aura.int.lakner.io` | yes | yes |
| **nip.io** (no domain needed) | `http://10-0-0-2.nip.io:3000` | yes | no |
| On the machine itself, or an SSH tunnel | `http://os.aura.localhost:3000` | yes (not Safari, see below) | no |
| Raw IP | `http://10.0.0.2:3000` | no, setup only | no |

## What each address needs

These were checked in Chromium, Firefox and WebKit (the engine of Safari).

| Address | What you set up |
|---|---|
| nip.io | Nothing, unless your router's DNS rebinding protection blocks it (see the nip.io section below). |
| `os.aura.localhost` | Nothing. **Safari** (and every iPhone and iPad browser) does not keep App Host sign-ins on `*.localhost`, so use `http://127-0-0-1.nip.io:<same port>` there. The desktop shows a bar with that link when the browser drops the sign-in. |
| HTTPS custom domain | DNS for the desktop name **and** `*.<parent>`, a wildcard certificate, a domain on a public suffix, an edge (reverse proxy) that keeps `Host`, sets `X-Forwarded-Proto` and `X-Forwarded-Host`, and passes WebSocket upgrades, `AURA_TRUSTED_PROXIES` set to that edge's exact address, and the domain in `AURA_DESKTOP_HOSTS`. See [Custom domain](#custom-domain). |
| SSH tunnel | Forward a local port to `127.0.0.1:3000` on the AuraOS machine, e.g. `ssh -L 3000:127.0.0.1:3000 you@box`, then open `http://os.aura.localhost:3000` (Safari: `http://127-0-0-1.nip.io:3000`). Any free local port works; App Hosts follow it. |
| Direct IP | Nothing, but it is setup only: the desktop opens, apps on App Hosts don't. A bar links to the matching nip.io address. |

An address shaped like an app host (`name--…`) is never the desktop: a name
no app uses answers *404*, a removed app's name *410*. An address the
browser's URL parser can't read (`foo.123`, `1.2.3.999`) answers *400*.

"HTTPS-only browser APIs" are what browsers allow only on a secure origin:
the clipboard API, microphone and camera, service workers, `crypto.subtle`.
On plain HTTP those features of AuraOS and its apps don't work.

## nip.io: no domain needed

[nip.io](https://nip.io) is public wildcard DNS: any name ending in
`<ip-with-dashes>.nip.io` resolves to that IP. `10-0-0-2.nip.io` and
`marklayer--10-0-0-2.nip.io` both resolve to `10.0.0.2`, so the desktop and
every app host work on port 3000 with no setup. sslip.io works the same way.

<Callout type="warn">
Some routers and resolvers refuse public names that resolve to private IPs
("DNS rebinding protection": Fritz!Box by default, Pi-hole/unbound with
private-address filtering, dnsmasq `stop-dns-rebind`). Symptom: the nip.io
name doesn't resolve at all. Allow `nip.io` in that filter, or use a domain.
</Callout>

## On the machine itself: `os.aura.localhost`

Browsers resolve `localhost` and every `*.localhost` name to the machine
itself, so `http://os.aura.localhost:3000` and its app hosts
(`marklayer--os.aura.localhost:3000`) need no DNS. Use `os.aura.localhost`,
not bare `aura.localhost`: only the first carries app hosts.

**Safari:** WebKit doesn't send an app host's sign-in cookie on
`*.localhost`, so every app would stop at *Open this app from AuraOS*. Open
`http://127-0-0-1.nip.io:3000` instead (the same machine through nip.io).
The desktop checks this itself when it starts on `os.aura.localhost` and,
when the browser drops the cookie, shows a bar with that link.

**SSH tunnel:** `ssh -L 3000:127.0.0.1:3000 you@box` forwards your local port
3000 to the AuraOS machine, and `http://os.aura.localhost:3000` (or
`127-0-0-1.nip.io:3000` in Safari) then works as above.

## Custom domain

Three one-time pieces, all on your side:

1. **DNS**: the desktop name and a wildcard for its parent, e.g.
   `box.aura.example.com` and `*.aura.example.com`, pointing to your edge
   (or straight to the AuraOS host).
2. **Certificate**: one wildcard, `*.aura.example.com`. App hosts use `--`
   instead of a dot (`marklayer--box.aura.example.com`), so one label is
   enough for every machine and every app.
3. **Route**: send `box.aura.example.com` **and** `*--box.aura.example.com`
   to the shell (`<host>:3000`), keeping `Host`, setting
   `X-Forwarded-Proto` and `X-Forwarded-Host`, and passing WebSocket upgrades.
4. **Trust and list**: `AURA_TRUSTED_PROXIES` and `AURA_DESKTOP_HOSTS` on the
   shell container (below).

The domain must end in a public suffix (`.com`, `.io`, `.de`, …). WebKit
rejects app host cookies under suffixes that aren't public, such as `.test`,
`.lan`, `.local`, `.home` or `.internal`, so apps don't open there in Safari.

```nginx
server {
    listen 443 ssl http2;
    server_name box.aura.example.com ~^[a-z][a-z0-9]{0,30}--box\.aura\.example\.com$;
    ssl_certificate     /etc/ssl/wildcard.aura.example.com/fullchain.pem;
    ssl_certificate_key /etc/ssl/wildcard.aura.example.com/privkey.pem;

    location / {
        proxy_pass http://10.0.0.2:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host  $host;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;   # map $http_upgrade → upgrade/close
        proxy_read_timeout 1h;
    }
}
```

**Trusting the edge.** Set `AURA_TRUSTED_PROXIES` on the shell container to
your edge's exact address as the shell sees it (comma-separated if there are
several). App hosts believe `X-Forwarded-Proto`, `-Host` and `-For` only from
those addresses. Without it the shell can't tell that the browser used HTTPS,
so the desktop refuses the `http://` app host addresses it gets and apps
don't open.

**Listing your domain.** Set `AURA_DESKTOP_HOSTS` on the shell container to
the domain(s) you open AuraOS at, comma-separated, without `https://`:

```yaml
environment:
  AURA_DESKTOP_HOSTS: box.aura.example.com
```

Its app hosts (`*--box.aura.example.com`) follow automatically. This stops
DNS rebinding: any website could otherwise point a name of its own at your
machine and reach AuraOS as that name. IP addresses, `localhost` and
`os.aura.localhost`, nip.io names and container names never need listing.
`sslip.io` and every other domain do.

`AURA_HOST_POLICY` decides what happens to an address that is not listed:
`report` (today's default) serves it and logs `unlisted-host`; `enforce`
refuses it with *400 This address is not one of this AuraOS's addresses*.
`enforce` becomes the default when App Hosts carry every app, so list your
domain now.

## Raw IP

`http://10.0.0.2:3000` opens the desktop for setup only. App hosts need a
label to prepend, so apps don't open there: the desktop shows a bar that
links to the nip.io address.

## Building apps

Every address above gives each app window its own App Host origin. What
that means for your code (reaching the shell, the runtime script, browser
storage) is in [Building an app for App Hosts](/docs/building-for-app-hosts).
