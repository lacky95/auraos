**TL;DR.** Every app with a UI opens on its own **App Host**:
`{label}--{the host AuraOS is open at}`, same scheme and port, served from
`/` with nothing rewritten. The shell picks the label. Service apps have no
UI and no App Host; machines reach them at `/api/proxy/<id>/…`.

| AuraOS opened at | An App Host of Notes |
|---|---|
| `http://10-201-1-2.nip.io:3000` | `http://notesabcd1234--10-201-1-2.nip.io:3000` |
| `https://lukas-01.aura.int.lakner.io` | `https://notesabcd1234--lukas-01.aura.int.lakner.io` |

How to write an app for it: [Building an app for App Hosts](/docs/building-for-app-hosts).

## Why an origin of its own

- **A real origin root.** Root-absolute URLs (`/api/…`, `/ws/…`, assets
  built at runtime) reach your own server. No base path, no rewriting.
- **Isolation.** Code on an App Host can't read the desktop's DOM, cookies or
  storage, nor another app's.

## Labels

The App Host registry assigns each installation a label, and each instance
of a multi-instance app its own. Labels follow `^[a-z][a-z0-9]{0,30}$`
(letters and digits, no hyphens: nip.io would read them as an IPv6 address).
A removed app's label is never given out again; it answers *410*.

Manifest `hosts[]` names are not served: only the labels the registry
assigns are.

## What the shell does

The shell checks the `Host` header before anything else. For a
`{label}--{anything}` the registry knows:

- **Sign-in first.** The desktop opens the window with a one-time handoff
  that sets an app cookie on that origin. Without it, nothing reaches the
  app: the page asks you to open the app from AuraOS.
- **`/_aura/*` is the shell's.** `/_aura/runtime.js` and the gateway
  `/_aura/os/` are answered by the shell, never by your app.
- **HTTP and WebSocket** are streamed to the instance. Upgrades are piped
  byte for byte, so subprotocols and your own pings pass through.
- **Nothing is changed**: no prefix stripped or added, no HTML/JS rewriting,
  no injected scripts. Redirects pass as sent.
- **`Host` is kept.** The shell adds `X-Forwarded-Host`, `X-Forwarded-Proto`,
  `X-Forwarded-Port`, `X-Forwarded-For`, `X-Aura-App-Id` and
  `X-Aura-Instance-Id`. Build absolute links from `X-Forwarded-Proto` and
  `Host`: behind an HTTPS edge the hop to the shell is plain HTTP.
- **A stopped app is started** on the first request. While it starts, a
  browser gets a page that reloads by itself (503, `Retry-After: 2`).
- An unknown label answers *404*. Every other host, including the desktop's
  own, goes to the shell.

## Framing and embedding

The desktop frames your App Host, cross-origin. If your UI sends
`Content-Security-Policy: frame-ancestors`, allow the desktop's origin, or
`*` for a private install. Remember that `frame-ancestors` is checked against
**every** ancestor, not just the parent.

## Limits

- **nip.io is plain HTTP.** Browsers switch off HTTPS-only APIs there
  (clipboard, microphone, camera, service workers, `crypto.subtle`), for
  the whole of AuraOS. Use a custom domain for those ([Reaching AuraOS](/docs/reaching-auraos)).
- **Raw IP access has no App Hosts**, so apps don't open there.
- **Browser storage is per origin.** Each App Host starts empty, and each
  address AuraOS is opened at has its own set of App Hosts.
